Jellyfin Web: next-episode autoplay

With Play next episode automatically on, Jellyfin Web expands a one-episode SyncPlay queue to the rest of the series, so a user who joins a group playing an episode gets an error and the player does not open (stock SyncPlay does the same). It is a per-user setting, and turning it off also stops next-episode autoplay outside SyncPlay. Jellyfin Web keeps the value it loaded, so the change applies once that user reloads the page or restarts the app.

Joining

Members whose client speaks SyncPlay v2 join a playing group without pausing everyone else. Stock jellyfin-web is v1 and always uses the classic wait.

Waiting for members

How long the group waits for a member to load a new item, a restarted item or the group's item when joining, before playing on without it. Starting a transcode can take a while. 3–300, default 30, and never shorter than the stall timeout.
How long the group waits for a member that stalled on its own, or is catching up after a seek, before playing on without it. The member is waited for again as soon as it reports. 3–120, default 10.
A rebuffer shorter than this does not pause anyone else. 0 pauses the group on every rebuffer. 0–10, default 2.

Connections

A member whose connection drops keeps its place this long and resumes where the group is if it comes back. 10–600, default 90.
How often v2 clients are told the group's position while playing. 1–60, default 5.
Running groups apply new wait timeouts and disconnect grace from the next check, about a second after saving, including a wait or disconnect already under way. A buffering grace already counting down, and the wait for the next beacon, keep the value they started with. No restart needed.
